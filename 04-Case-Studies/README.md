# QA Case Studies

## Overview

This section presents selected QA testing projects completed as practical demonstrations of manual software testing skills.

The case studies demonstrate the ability to:

- Understand application requirements
- Define testing scope
- Design test scenarios
- Create test cases
- Prepare test data
- Execute manual tests
- Perform exploratory testing
- Identify and document defects
- Perform retesting when applicable
- Analyze test results
- Produce structured QA reports

---

## Case Studies

### 1. Banking Application Testing

A manual QA testing project performed on a demo banking application.

The project covers:

- Customer authentication
- Bank Manager authentication
- Customer dashboard
- Account information
- Account balance
- Transaction history
- Deposits
- Withdrawals
- Customer and account management
- Logout and navigation

Testing activities included functional testing, positive and negative testing, exploratory testing, Boundary Value Analysis, Equivalence Partitioning, regression testing and defect verification where applicable.

[View Banking Application Case Study](./Banking-Application.md)

---

### 2. E-commerce Testing — SauceDemo

A manual QA testing project performed on the SauceDemo e-commerce application.

The project covers:

- Login
- Product display
- Product sorting
- Product details
- Add to cart
- Shopping cart
- Product removal
- Checkout information
- Order overview
- Order completion
- Logout
- Navigation

Testing activities included functional testing, positive and negative testing, exploratory testing, smoke testing, regression testing and defect reporting.

[View E-commerce Case Study](./E-commerce-SauceDemo.md)

## Testing Approach

The projects were conducted using a structured QA process covering:

```text
Requirements
     ↓
Test Planning
     ↓
Test Scenarios
     ↓
Test Cases
     ↓
Test Data
     ↓
Test Execution
     ↓
Evidence
     ↓
Defect Reporting
     ↓
Test Summary
```
## 🎯 Purpose

These case studies are personal QA projects created to demonstrate practical software testing skills and experience.

They are not presented as professional client projects.
