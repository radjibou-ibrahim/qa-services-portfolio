## 📋 Typical Bug Report

A bug report may contain:

| Field | Description |
|---|---|
| **Bug ID** | Unique identifier |
| **Title** | Short description of the issue |
| **Environment** | Browser, OS, device, etc. |
| **Preconditions** | Conditions required before testing |
| **Steps to Reproduce** | Clear reproduction steps |
| **Expected Result** | Expected application behavior |
| **Actual Result** | Observed behavior |
| **Severity** | Impact of the defect |
| **Priority** | Urgency of fixing the defect |
| **Evidence** | Screenshot/video when relevant |
| **Status** | Open, Fixed, Retest, Closed, etc. |

> 🎯 **Objective:** Provide developers with enough information to reproduce and understand the issue quickly.>>

## 📊 Testing Techniques
Depending on the application, I may use:
Functional Testing
Verifying that features behave according to their requirements.
Positive Testing
Checking that valid inputs and expected user actions work correctly.
Negative Testing
Checking how the application behaves with invalid or unexpected inputs.
Boundary Value Analysis
Testing values around the limits of an accepted range.
Equivalence Partitioning
Dividing input data into representative valid and invalid groups.
Exploratory Testing
Investigating the application dynamically to discover unexpected issues that may not be covered by predefined test cases.
Regression Testing
Verifying that recent changes have not introduced defects into existing functionality.
Smoke Testing
Performing a quick validation of critical functionality before deeper testing.
